# Изменение клиентской сборки

Нужны Git и PowerShell 7. Для проверки в игре — Create Launcher и отдельная тестовая установка.

## Работа с пакетом

1. Измените нужные моды или конфиги в `pack/`. Сохраняйте лицензии и происхождение сторонних файлов.
2. Для нового мода укажите страницу автора, версию, загрузчик и причину добавления в PR.
3. Выполните `pwsh ./release_client.ps1` из корня репозитория.
4. Проверьте изменения `pack/manifest.json` и состав `release/client.zip`.
5. Проверьте чистую установку, обновление и вход на сервер. Для изменений взаимодействия проверьте установку и разрушение блоков.
6. Запишите изменения версии только в [CHANGELOG.md](CHANGELOG.md). В [RELEASE.md](RELEASE.md) оставляйте ссылки на чейнджлог и установку без дублирования изменений и скриншотов.

`release_client.ps1` обновляет хеши файлов, собирает ZIP и создаёт SHA-256 архива. Он не публикует релиз и не заменяет проверку модов на безопасность.

## Что не добавлять

Миры, аккаунты, токены, логи, Java, файлы Minecraft и серверные секреты. Серверный NeoLogin не должен попадать в клиент. Не переносите всю папку работающей игры в `pack/`.

Для `pack/` отключена нормализация строк Git: байты файлов должны совпадать с хешами манифеста. После изменения содержимого запускайте упаковку заново.

В PR опишите проблему, список изменённых модов/конфигов и результаты проверок. Не выдавайте успешную упаковку за проверку игры.

Порядок выпуска — [docs/RELEASING.md](docs/RELEASING.md). Об уязвимостях сообщайте по [SECURITY.md](SECURITY.md).
