# Выпуск клиентской сборки

## Подготовка

1. Проверьте версии Minecraft и NeoForge в `pack/manifest.json` и совместимость с конфигурацией лаунчера.
2. Проверьте содержимое `pack/`: только распространяемые файлы клиента, без миров, учётных данных и серверных секретов.
3. Выполните `pwsh ./release_client.ps1` из корня репозитория. Скрипт обновит манифест и создаст `release/client.zip`, `release/client.zip.sha256`.
4. Сверьте локальную сумму: `Get-FileHash ./release/client.zip -Algorithm SHA256`.
5. Проверьте чистую установку и обновление предыдущего клиента через отдельную тестовую копию лаунчера.
6. Запишите изменения версии только в `CHANGELOG.md`. В `RELEASE.md` оставьте ссылки на чейнджлог и установку без дублирования изменений и скриншотов. Если меняются версии Minecraft/NeoForge, обновите также заголовок релиза в workflow.

Для локального архива поместите `client.zip` рядом с тестовым лаунчером и очистите `pack_release_url` и `pack_url` в его `launcher.json`. Меняйте конфигурацию только тестовой копии.

## Текущее поведение CI

Workflow `Client release` запускается при push в `main`, теге `v*` или вручную. Он упаковывает клиент и публикует архив с контрольной суммой.

Для тега используется его имя, для остальных запусков — `client-<первые 7 символов commit>`. Описание берётся из `RELEASE.md`. Повторный выпуск с уже существующим именем может завершиться ошибкой.

Релизы не помечаются как предварительные. Лаунчер использует последний стабильный релиз GitHub, поэтому push в `main` следует считать выпуском для игроков.

## После публикации

Проверьте наличие обоих файлов в релизе и установку через стандартный источник лаунчера. SHA-256 сверяется лаунчером с digest из GitHub API; файл `client.zip.sha256` предназначен также для ручной проверки.

Если выпуск неисправен, верните совместимое содержимое пакета отдельным исправляющим коммитом и выпустите новый релиз. Не удаляйте пользовательские миры и настройки для восстановления клиента.

Для каждого опубликованного тега `client-*` нужна отдельная запись в `CHANGELOG.md`. Workflow `Release notes` проверяет их наличие и заменяет описания опубликованных Releases ссылками на чейнджлог. README описывает текущее состояние проекта без скриншотов и истории выпусков. Изменения только Markdown и `docs/` не выпускают новый архив клиента. Перед публикацией проверьте готовый архив реальным `LauncherService.ApplyPack`, а не только его упаковку и хеши.
